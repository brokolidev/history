집에서 학습용으로 서버를 하나 돌리려다보니 Wake On Lan이란 기능을 알게되었다.

전기세 좀 덜먹게 할려고..ㅎ

여튼.. Wake On Lan기능을 사용하려면 랜카드, 공유기에서 지원을 해 주어야 하고 OS에서도 설정해주어야 한다.

요즘 대부분의 랜카드와 공유기는 지원하는것으로 알고있다.

공유기 설정방법은 공유기 메뉴얼을 참조하면 된다.ㅎ

여기서는 Cent OS에서 쓸데없이 삽질했었던 소중한 내용들을 기록하려 한다.

여튼... 나는 Cent OS 5.6을 설치하고 WOL기능을 적용하려 시도했다.

일단 Windows 7에서는 동작이 잘 되는것을 우선 확인하였다... (관련내용은 인터넷을 뒤지면 찾을 수 있다.)

그리고 리눅스 명령어는 인터넷을 뒤저셔 알아냈다.

/sbin/ethtool -s eth0 wol g

==> eth0은 자신의 장치명을 입력...

근데.... 젠장!!!!

아래와 같은 메시지가 나타났다.

Cannot get current wake-on-lan settings: Operation not supported not setting wol

아래 메시지 뿐만 아니라 모든 ethtool 다른 옵션 명령어들도 지원되지 않는다는 말뿐이었다.

ethtool eth0 명령어를 사용해봐도 검색했던 결과와는 달리 단순히 랜선이 연결되어있다는 메시지뿐....

절망이다...

인터넷을 뒤져보니.. 뭐.. 원래안된다는둥... 명확한 답을 찾기는 힘들었다....

(이상한 글들이 많아서 혼동을 참... 많이했다....--ㅋ 개뻘짓...)

여튼... 여차여차 뒤져봤는데...

대충 깨닳은것은... 가상화 지원을 위한 xen 때문이었다... 젠장..........

CentOS를 설치할때 뭣모르고 대충깔았던탓이었던듯....

그래서 그냥 xen kernel을 삭제하고 kernel 최신버전을 다시 설치했다.

1. yum install kernel --> 커널 설치

2. yum remove xen kernel-xen --> xen kernel 삭제

필요하다면 grub을 수정하여 부트메뉴를 변경한다.

vim /etc/grub.conf

그리고 재부팅후

/sbin/ethtool eth0 명령어를 실행하면 이전과는 달리 각종 Ethernet관련 정보들이 나타남을 확인할 수 있다.... 하하하...

(혹시 커널 재설치 후 이더넷 디바이스를 찾지못한다면 /lib/modules 아래 자신장치의 .ko파일을 찾으면 분명 있을것이다.

어떤파일인지는 /sbin/lspci명령어로 장치를 찾고 ko파일이 무엇인지 인터넷을 뒤져보도록.....)

그리고

/sbin/ethtool -s eth0 wol g

명령어를 다시 실행하면... 아무 메시지없이 잘 실행된다..... 하하하하하!!!!

완전 대~박.ㅋ

이제 컴터를 종료해보자.ㅋ

과감히 root계정으로

halt

명령을 때리시길~~~

컴퓨터가 종료되었지만 랜선이 꽃혀있는 이더넷 장치는 시퍼런 불이 계속 들어와 있는것을 확인할 수 있다.ㅎㅎㅎ

외부에서 공유기에 접속하여 wake on lan기능을 사용하면....

정말 신기하게 원격으로 내 컴퓨터를 켤수 있다는것을 테스트 해 볼 수 있다.ㅎ

부팅시 항상 적용되도록 설정하려면....

/etc/sysconfig/network-scripts/ifcfg-eth0 파일을 수정한다.. 없다면 인터넷을 뒤져서 어떻게 해야하는지 찾아본다...

여튼 위의 내용에

ETHTOOL_OPTS="wol g"

를 추가하고 시스템을 재시작하면 항상 적용된 상태로 부팅된다.ㅎ

여기서뭐.... 추가로 대부분 유동ip를 사용할테니... 공유기 제조사나 혹은 다른 무료 ddns를 제공해주는 서비스를 사용하면....

도메인으로 잘~~~ 접속할 수 있다.ㅋ

이상~ 끝!!!

귀찮아서 이만.......
