오전에 laradock으로 mysql과 nginx로 개발 환경을 구축하는 글을 포스팅 했는데,

이게 Laravel은 어떤지 모르겠지만 mysql 8 이상에서는 password 함수를 지원하지 않는 것 때문에

상당한 고난이 예상된다.

이에 따라 DB를 mariadb로 변경하고자 하니 자꾸 mariadb container가 업이 되지 않아 지웠다 깔았다만 수 차례...

아직 근본적인 솔루션이 나온 것은 아니지만 임시적으로 동작하게 하는 방법이 있다.

docker-compose.yml 파일 수정

```javascript
### MariaDB ##############################################
mariadb:
build:
context: ./mariadb
args:
- http_proxy
- https_proxy
- no_proxy
volumes:
- ./config:/etc/mysql/conf.d
- ./data:/var/lib/mysql
ports:
- "${MARIADB_PORT}:3306"
environment:
- MYSQL_DATABASE=${MARIADB_DATABASE}
- MYSQL_USER=${MARIADB_USER}
- MYSQL_PASSWORD=${MARIADB_PASSWORD}
- MYSQL_ROOT_PASSWORD=${MARIADB_ROOT_PASSWORD}
networks:
- backend
command:
mysqld --innodb-flush-method=littlesync --innodb-use-native-aio=OFF --log_bin=ON
```

결국 저 Data Volume 때문인 듯 한데 윈도에서만 발생하는 오류인 듯 하다.

위와 같이 volume path를 변경해주고,

아래쪽에 command 부분도 추가해준다. 저 부분은 -(대시)가 없으므로 주의!

laradock > mariadb 폴더 안에 my.cnf에 다음을 추가한다.

```javascript
[mysqld]
innodb_flush_method=littlesync
innodb_use_native_aio=OFF
log_bin=ON
```

이후 docker-compose up mariadb 해서 정상 동작하는지 확인한다.

postgre나 다른 DB를 사용하던지 해야지... 이거 원
