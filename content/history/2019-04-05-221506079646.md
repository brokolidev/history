다음은 PHP와 FPM이다.

PHP는 알겠는데 FPM이 뭔가?

nginx는 PHP 어플리케이션에 흔히 사용되던 아파치 서버와는 달리 PHP를 자체적으로 해석하지 못한다.

따라서 일종의 3th party 또는 Middleware 개념으로 nginx와 PHP 사이에서 통신을 담당한다고 보면 된다. (그래서인지 모르겠는데 nginx에서 PHP 어플리케이션에 접속하면 아주 미세한 딜레이가 느껴지는건 느낌적인 느낌인가)

암튼 설치해보자.

그냥 sudo apt install php-fpm 하면 7.2로 설치가 된다. 현재 최신 버전은 7.3이지만 2나 3이나 뭔 큰 의미가 있겠나... 그냥 넘어가자.

자 설치가 완료되고 nginx 기본 default root인 /var/www/html/ 에 들어가서  index.php 파일을 하나 만든 뒤 실행해보면 원했던 결과를 얻을 수 없을 것이다.

nginx에서 fpm이 동작하도록 config를 만져줘야한다.

Nginx를 사용하게 되면 자주 만나게될 메시지

Nginx가 아파치 베이스이기 때문에 설정은 거의 비슷하다고 보면 된다.

디폴드 설정 경로는 /etc/nginx/sites-available/default 요기 있다.

여기서 기본적인 Nginx의 사이트 설정에 관련된 구조를 이해하고 넘어가자.

Nginx에 Virtual Host를 추가하고 싶다면 위 sites-available 경로 안에 config파일을 만든 뒤(보통 도메인명으로 파일을 만들어 구분을 쉽게 한다) sites-enabled 경로에 link를 생성하는 방법을 쓴다.

직접 해보자.

일단 위 default파일을 test.com으로 하나 카피해 둔다.

열어보면 뭐 설명이 막 써있는데 다 지운뒤 아래 설정으로 변경한다.

```nginx
server {
    listen 80;

    root /var/www/html;
    index index.php index.html;
    server_name test.com www.test.com;

    location / {
        try_files $uri $uri/ =404;
    }

    location ~ \.php$ {
        include snippets/fastcgi-php.conf;
        fastcgi_pass unix:/var/run/php/php7.2-fpm.sock;
        fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
        include fastcgi_params;
    }
}
```

도메인이 있다면 위 코드에서 test.com을 원하는 사이트명으로 변경해서 사용하면 됨.

저장 후 php-fpm와 nginx를 재시작 하기 전에 반드시 링크 파일을 sites-enabled 디렉토리에 생성해줘야한다.

그리고 기존에 걸려있던 default는 삭제해버리도록 하자.

```bash
sudo rm /etc/nginx/sites-enabled/default
sudo ln -s /etc/nginx/sites-available/test.com /etc/nginx/sites-enabled/test.com
sudo service php7.2-fpm restart
sudo service nginx restart
```

여기까지 하면 일단 PHP를 해석할 수 있는 Nginx 웹서버 구성이 완성 된 것이다.

다음은 MariaDB를 연동해보자.

이런저런걸 찾다보니 MySQL은 5.7버전 이후부터 User 테이블에 Password 필드가 빠진 듯 하다.

MariaDB는 변동이 없는 것 같으니 패스...(귀찮귀찮)

설치 후에 mysql_secure_installation을 실행하여 보안 설정을 향상시켜주도록 권장하고 있지만... 패스워드 복잡도를 올리면 단순한 패스워드 사용이 안되니 참고.

workbench를 사용하기 위해서 외부에서 접속할 수 있는 사용자 생성과 컨피그 설정을 해주도록 하자.

```sql
sudo mysql

MariaDB> create database tester default character set utf8;
MariaDB> create user tester@localhost identified by 'tester';
MariaDB> grant all privileges on tester.* to tester@localhost;
MariaDB> create user tester@'%' identified by 'tester';
MariaDB> grant all privileges on tester.* to tester@'%';
MariaDB> flush privileges;
```

mysql -u tester -p 한뒤 로컬로 접속되는지 우선 확인한다. 오케이 로컬은 이상 없다.

그럼 워크벤치에서 붙어보자.

mysql은 3306 포트를 사용하기 때문에 AWS 방화벽에서 3306을 오픈해줘야한다.

UFW를 enable 시켰다면 UFW 에서도 allow를 해준다.

워크벤치 설정 후 Test connection을 해보면 접속이 되지 않을 것이다.

바로 접속 불가능하다는 에러 메시지가 뜬다면 서버에서 접속이 안된다는 메시지를 보낸 거기 때문에 방화벽은 오픈되어있는 것이고, 행이 걸린다면 방화벽이 오픈되지 않아 응답을 못받고 timeout이 나는거다.

![Image](/img/history/naver/2019/2019-04-05-221506079646/photo_04.png)

요렇게 바로 끊어지면 일단 방화벽은 열렸다.

방화벽도 열렸고 유저도 정상 생성 했는데 왜 접속이 안될까. 게다가 메시지가 그냥 접속 못하겠다는건데.

mysql은 기본 설치하면 원격에서 접속을 할 수 없게 컨피그가 설정 되어있다.

```bash
sudo vim /etc/mysql/mariadb.conf.d/50-server.cnf

# Instead of skip-networking the default is now to listen only on
# localhost which is more compatible and is not less secure.
# bind-address          = 127.0.0.1

sudo service mysql restart
```

위와 같이 컨피그에 접속하여 bind-address를 주석처리한 뒤 mysql 서비스를 재시작해보자. 접속이 잘 될것이다.

자 여기까지면 모두 끝! 일줄 알고 그누보드를 다운받아 설치했다.

근데... 로그인이 안된다.

사실상 이거때매 몇 시간을 헤맸는데 생각해보니 예전에도 비슷한 경험이 있었던 것 같다.

그누보드 로그인이 안되는 경우는 여러가지가 있지만

이 경우는 php.ini에서 secure cookie 설정이 활성화 되어 있어서 문제가 되었다. 해당 설정을 주석처리해주면 이상이 없을 것이다. 또 그누보드 일부 기능은 gd 라이브러리가 필요하므로 자동 설치 되지 않는 GD는 별도 설치해야한다. sudo apt install php-gd 하면 될것이다.

그누보드 설치까지 다 적자니 너무 시간이 걸릴 것 같아서 오늘은 일단 여기까지.
