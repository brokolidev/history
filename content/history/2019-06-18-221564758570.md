최근 개발에 사용하는 환경은 이러하다.

1. vagrant로 로컬 개발 환경 구축

2. 개발 된 코드를 private github에 push

3. 실서버에서는 해당 저장소에서 pull

그런데 이 vagrant가.. 뭐 다른건 다 괜찮은데 Workbench로 DB 접속할때 한참 걸린다.

로컬에서 가상머신으로 접속하는건데 빨라야 되는거 아닌가? .. 지식의 한계.

아므튼 그래서 해봐야지 해봐야지 하던 Docker를 사용해서 개발환경을 대체해보기로 한다.

일단 윈도우용 Docker는 2가지가 있는 듯 하다.

네이티브 윈도우용 Docker를 설치하면 Virtualbox를 사용할 수 없기 때문에

Docker Toolbox라는게 더 이상 신규 버전이 나오지 않음에도 많이들 쓰는 듯 하다.

난 뒤를 잘 돌아보지 않는  없는데다가 순수주의자이므로 네이티브로 설치해보기로 한다. (Vagrant 안녕)

Docker에 대한 글들은 여기저기 많으므로 잘 조합해서 읽어보면 꽤 도움이 된다.

어쨋든 핵심은 별도의 가상 OS를 올리지 않고 다이렉트로 자원을 사용하기 때문에 빠르고, 컨테이너 사용으로 별도의 유지보수가 필요 없기에 편리하다는 점.

이 포스팅에서는 Docker를 설치하여 여러개의 웹사이트를 올려보는 것을 목표로 한다.

![Image](/img/history/naver/2019/2019-06-18-221564758570/photo_01.png)

일단 도커를 다운받은 뒤 설치한다.

설치가 완료되면 로그아웃을 한 번 하고 다시 로그인하면 다시 Hyper-V 때문에 자동으로 재부팅된다는 메시지가 뜬다. 순순히 재부팅이 될 때까지 기다려준다.

![Image](/img/history/naver/2019/2019-06-18-221564758570/photo_02.png)

잘 설치가 되었다.

이제 필요한 서비스를 설치할 단계인데, 우리는 PHP 환경을 사용하므로 Laradock을 사용해서 구성해보기로 하자.

Laradock은 또 뭣인가? Laradock.io에 들어가서 살펴보기로 한다.

![Image](/img/history/naver/2019/2019-06-18-221564758570/photo_03.png)

Full PHP 개발 환경이란다.

PHP 개발에 필요한 Docker 이미지들을 모아서 패키지로 구성해놓은거 정도로 보면 되겠다.

아래 나와있는 가이드대로 진행을 해본다.

```bash
git clone https://github.com/Laradock/laradock.git
```

laradock이라는 폴더가 생길 것이다.

```bash
cp env-example .env
```

.env 파일을 만들어 구성할 이미지의 환경을 설정해준다.

뭐 다른 것은 없고 우리의 디렉토리 구성은 아래와 같으므로

```text
+ laradock
+ project1
- img
- js
- css
+ project2
- img
- css
```

경로만 잘 지정해준다. 기본 설정에서는 laradock에서 ../ 이 /var/www 로 잡혀있으므로 손볼것은 없다.

이제 Docker 이미지를 띄우기 전에 Nginx 설정을 손볼 차례다.

laradock 폴더 안에 들어가면 각 서비스 컨테이너에 대한 설정들을 손볼 수가 있다. nginx/sites/ 에 들어가면 default.conf가 있는데 이걸 참고로 해서 각 프로젝트에 쓰일 도메인과 폴더들을 지정해준다.

윈도우에서 도커를 띄울때는 보통 Powershell을 사용한다.

설정이 끝나면

```bash
docker-compose up -d nginx mysql
```

위 명령어로 서비스를 띄워본다.

```bash
docker-compose ps
```

위 명령어로는 현재 up 되어있는 컨테이너를 확인해볼 수 있다.

![Image](/img/history/naver/2019/2019-06-18-221564758570/photo_04.png)

각 컨테이너로 진입할때는 아래와 같은 명령어를 사용한다.

```bash
docker exec -it laradock_workspace_1 bash
```

이후 지정한 프로젝트 루트에 index.php를 작성해보자. (hosts 파일에 지정한 도메인 등록은 당연히 해야겠지)

경로를 잘 지정했다면 Nginx가 페이지를 잘 띄워줄텐데 문제는 mysql이다.

로컬 PC에서 워크벤치로 접속해보면 원격접속이 모두 허용되어 있어 문제 없이 잘 접속이 될텐데,

![Image](/img/history/naver/2019/2019-06-18-221564758570/photo_05.png)

문제는 nginx에 올려놓은 서비스가 mysql로 접속을 시도할 때이다.

host를 localhost나 IP주소를 적으면 접속이 되지 않고, 반드시 **'mysql'** 로 적어야 한다.

또 하나 마리아DB가 아닌 mysql을 사용하는 경우 발생하는 문제는 authentication 문제이다.

8.0이상 버전에서 인증 방식이 변경되어 발생하는 문제로, 2가지의 해결 방법이 있다.

첫 째는 유저를 신규 인증 방식으로 재설정하는 방법

```sql
ALTER USER 'root'@'localhost' IDENTIFIED WITH mysql_native_password BY 'password';
flush privileges;
```

두 번째는 그냥 옛날 방식으로 설정을 바꾸는 법.. 이 있었는데 아무리 찾아도 없네 이런

난 두 번째 방식으로 해결했지만 보안적인 이유이니 첫 번째 방식으로 사용하도록 하자...

사이트를 추가하는 경우 laradock에 있는 nginx config 파일을 추가하거나 수정 한 뒤,

```bash
docker-compose down
docker-compose build nginx php-fpm
docker-compose up -d nginx mysql
```

요렇게 재시작 해주면 된다.

일단 여기까지 진행했다면 테스트 환경으로 사용하는데는 큰 무리가 없다.

그런데 여러개의 사이트를 올렸을 때, URL이 꼬이는 현상이 있다.

정확히 말하자면 도커를 올리고 최초 접속한 사이트는 문제가 없는데

등록해둔 다른 사이트에 접속을 하면 최초 접속한 사이트의 URL에 /var/www~ 가 붙어서 나온다.

이건 Opcache 때문인지 php-fpm을 함께 빌드를 안해줘서 그런지 모르겠지만

암튼 현재는 laradock의 .env 파일에서 opcache 설정을 false로 변경하고 nginx 설정 재적용하는 경우 php-fpm도 함께 빌드를 다시해서 사용하니 문제가 발생하지 않았다.
